# Herdr의 모든 Claude·Codex 대화에 Jev 적용

작성·재검증: 2026-11-06. 대상은 개인 Windows `herdr-app`과 `herdr-core`이며 별도 `herdr` TUI가 아니다.

## 목표와 현재 환경

사용자가 Herdr의 기존·신규·복원 대화에 작업을 입력하면 Jev가 자동으로 요청을 분류하고 현재 Claude Code 또는 Codex에 짧은 참고 문맥을 제공한다. `/jev` 입력이나 프로젝트별 설치는 필요 없다. 일반 셸은 AI를 실행한 뒤 대상이 된다.

사전 조사 당시 39개 공간, 43개 탭(Claude 10, Codex 25, 셸 8), 8개 Git 저장소와 기본 작업 폴더를 포함한 17개 worktree가 있었다. 연결된 대화 38개의 최근 요청·결과를 살폈다. PHM·ATLAS의 역할 공간 대부분은 동일 소스를 공유하고, HyunExplorer의 기획·개발·검증은 실제 worktree로 분리되어 있다. 이 수치는 조사 시점의 관측값이며 설치 조건이 아니다.

## 설계 재검증과 결정

| 확인 항목 | 근거와 결정 |
|---|---|
| 모든 대화의 진입점 | Claude `~/.claude/settings.json`, Codex `~/.codex/hooks.json`의 사용자 전역 `UserPromptSubmit`. 현재 두 파일에 Herdr 세션 연결 훅이 존재한다. 기존 훅을 보존하며 별도 핸들러를 추가한다. |
| 현재 요청에 판단 반영 | 두 엔진 모두 `hookSpecificOutput.additionalContext`를 지원한다. 동기 훅으로 요청 직전에 판단하며 실패 시 기본 작업을 계속한다. |
| 현재 세션 식별 | 훅의 `session_id`, `cwd`, `HC_TERMINAL_ID`를 사용한다. 과거 저장 경로로 현재 역할을 확정하지 않는다. |
| 오래된 복원 정보 | 사전 조사에서 과거 경로 12건과 ID 미확정 연결이 발견됐다. 복원 데이터를 자동 수정하는 대신 Jev에서 의존하지 않는다. 이 문제의 수리는 별도 작업이다. |
| 역할·권한 | 작업 이름·폴더명은 참고 자료일 뿐 권한이 아니다. 프로젝트 AGENTS/CLAUDE 지침과 직접 사용자 지시를 현재 AI가 적용한다. Jev가 권한을 부여하거나 역할을 자동 변경하지 않는다. |
| API | `POST https://api.typesafe.ai/v1/systemone`, Bearer 인증, `state`와 이름별 `questions`. Choice의 `criteria`는 선택지 설명 맵이다. |
| 모델 | 재현 가능한 기본값 `jev-1.14.0`. 응답의 실제 모델과 사용량을 기록한다. API 속도·품질·절감 효과는 실측 전 보장하지 않는다. |
| 기존 대화 적용 | 설정 파일 설치와 실제 훅 호출은 다르다. Codex는 정확한 훅 정의의 신뢰 등록을 확인한다. 이미 열린 세션의 새 설정 반영은 별도 확인하고 미확인 상태를 숨기지 않는다. |
| Windows 실행 | 공통 Node helper와 PowerShell 진입점. 상대 경로나 현재 작업 폴더의 실행 파일에 의존하지 않는다. 새 상주 서비스·native 빌드는 필요 없다. |

위 계약으로 구현 가능한 것을 확인했다. 공개 `herdr-jev` TUI 플러그인을 그대로 설치하지 않고 현재 앱의 기존 확장 지점을 사용한다.

## 요청 처리

1. `SessionStart`는 세션 준비 상태만 기록한다. API는 호출하지 않는다.
2. `UserPromptSubmit`은 Herdr 터미널인지, 정상적인 세션 식별자인지 확인한다. 엔진 내부 하위 에이전트의 중복 훅은 제외한다. 별도 Herdr 터미널에서 받은 작업 요청은 독립 요청으로 처리한다.
3. 실제 cwd의 Git 루트·브랜치를 읽고, core의 같은 터미널 이름을 가능한 경우 참고한다. core 조회 실패가 작업을 막지 않는다. 프로젝트 소스를 검색하거나 변경하지 않는다.
4. 현재 요청과 해당 세션의 제한된 최근 대화만 준비한다. 긴 입력은 잘렸음을 명시하고 흔한 비밀값 형식을 가린다. 전체 대화·문서·첨부·도구 출력·환경변수 전체를 보내지 않는다.
5. 하나의 Jev 요청에서 작업 종류(설명/조회/계획/구현/검증/운영/기타), 필요한 검증 방식, 추가 문맥 필요 여부를 묻는다. 불확실한 분류는 지시로 사용하지 않는다.
6. 응답 스키마와 선택지·확률을 검증한다. 검증한 선택지만 고정된 참고 문장으로 바꾼다. API가 반환한 임의 문장을 시스템 지시로 주입하지 않는다.
7. 현재 모델이 기존 권한·프로젝트 규칙에 따라 작업한다. Jev는 모델 교체, 다른 탭 전송, 작업트리 생성, 승인 우회, 테스트 통과 판정을 실행하지 않는다.
8. 응답 종류·소요 시간·모델·토큰 수·세션 ID·요청별 확인값을 로컬에 기록한다. 원문 요청·답변·API 키는 기록하지 않는다. 실패도 별도 상태로 표시한다. 엔진별 마지막 훅의 이벤트 종류·환경변수 존재 여부·제한된 오류 코드도 건강 상태 파일 1개에 기록한다. Herdr 밖에서는 진단 메타데이터만 갱신하고 API를 호출하지 않는다.

연속 대화의 최근 문맥은 원래 Claude/Codex 저장소의 정확한 세션 파일에서만 제한적으로 읽는다. 잘못된 경로·다른 세션·허용 저장소 밖 파일이면 최근 대화를 제외한다. 가림 처리는 모든 개인정보를 완벽하게 검출하는 장치가 아니므로, 선택된 현재 요청·최근 문맥이 TypeSafe로 전송된다는 점은 운영 전제다.

## 구현 범위

- `scripts/jev/`: 공통 판단 helper, PowerShell 훅, API 키 로컬 입력, 상태/진단 CLI.
- `scripts/install-jev.cjs`: 기존 설정 보존·중복 방지·고유 백업·정확한 Codex 훅 신뢰 등록. 설치된 helper는 `%LOCALAPPDATA%/Herdr/jev/`에서 실행한다.
- `mods/jev-status/`: 현재 대화의 최근 요청 결과·오류·연결 준비 상태를 보여주는 창.
- `mods/workspace-status-progress/`: 현재 터미널의 간략한 Jev 상태 표시와 상세 창 열기.
- `tests/jev-*.test.cjs`: 실패·입력·경로·설치·UI 회귀 검증. OS 임시 폴더를 사용하고 finally에서 정리한다.

새 프로젝트는 전역 훅을 자동 상속한다. 미리 등록한 프로젝트 목록은 사용하지 않는다. 다른 AI 엔진·원격 컴퓨터는 이 Windows 구현의 적용 범위가 아니며 별도 어댑터가 필요하다. Herdr 밖의 일반 Claude/Codex 세션은 처리하지 않는다.

## 자격 증명과 실패 처리

- 이름은 `TYPESAFE_API_KEY`다. 코드·Git·채팅·명령 인수에 키를 넣지 않는다.
- 기본 로컬 입력 절차는 `Read-Host -AsSecureString`과 Windows 사용자 DPAPI로 저장한다. 매 요청에서 읽으므로 기존 Herdr/core 프로세스가 오래된 환경변수를 가지고 있어도 새 키를 사용할 수 있다. 환경변수도 지원한다.
- API 주소는 고정 HTTPS 호스트이며 리디렉션을 따라 키를 다른 호스트에 보내지 않는다.
- API 시간 제한·응답 크기 제한을 둔다. 요청 앞에서 장시간 재시도하지 않는다. 키 없음·401/403·429·통신 오류·비정상 JSON·알 수 없는 선택지를 서로 구분한다.
- 오류 시 사용자 요청을 막지 않고 `Jev 미적용` 상태를 남긴다. 선택지가 불확실하면 현재 AI의 원래 판단을 유지한다.
- 하나의 요청에서 반복 훅/재진입이 생겨도 중첩 실행하지 않는다. 단순히 문장이 같다는 이유로 사용자의 다음 요청을 캐시하지 않는다.

## 설치·검증·복구 순서

1. 문서 계약을 공식 API·설치 코드와 대조한다. → 위 재검증 표.
2. helper·설치·표시 기능을 개발하고 로컬 모의 API로 검증한다.
3. 변경된 파일만 백업 후 설치한다. 기존 세션 복원 훅·사용자 설정·실행 중 AI를 유지한다.
4. 사용자가 키를 로컬 입력한다. 합성 문장으로 실제 API를 검증한다. 키는 출력하지 않는다.
5. Claude와 Codex 각각 신규·재개 세션의 훅 실행과 문맥 전달을 검증한다. 진행 중인 사용자 업무에 임의 프롬프트를 보내지 않는다.
6. 현재 대화들은 다음 실제 사용자 요청의 수신 기록으로 적용을 확인한다. 아직 요청하지 않은 세션은 확인 전 상태로 남긴다.
7. 새 워크스페이스의 첫 요청에도 같은 동작이 적용되는지 확인한다. Herdr 표시 오류·API 실패 복구·키 없는 동작을 검증한다.
8. 문서와 기준 개선 기록에 실행한 검사와 미검증 항목을 기록하고 작업 파일만 커밋한다.

복구는 Jev 소유 훅만 제거하거나 전용 설정에서 비활성화하고 이번 UI 파일만 이전 백업으로 돌린다. 전체 Claude/Codex 설정을 과거 백업으로 덮어쓰지 않는다. API 키·개인 상태·사용자 대화는 Git에 포함하지 않는다.

## 설치와 운영 명령

저장소 루트에서 사용자 권한으로 설치한다. 사용자 설정을 쓰므로 제한된 AI 실행 환경에서는 해당 파일 쓰기 승인이 필요하다. 관리자 권한이나 core 종료는 필요 없다.

```powershell
node scripts/install-jev.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/jev/set-key.ps1

# 합성 문장으로 실제 API 시험. 비밀값은 출력하지 않는다.
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA/Herdr/jev/hook.ps1" -Mode probe

# 전체 로컬 AI의 마지막 호출 상태
node "$env:LOCALAPPDATA/Herdr/jev/jev.cjs" status

# 즉시 비활성/재활성: 프로세스 재시작이나 전역 권한 변경 없음
node "$env:LOCALAPPDATA/Herdr/jev/jev.cjs" disable
node "$env:LOCALAPPDATA/Herdr/jev/jev.cjs" enable

# 실제 엔진 시험: 새 임시 폴더, 합성 요청, 기존 대화에는 입력하지 않음
node scripts/verify-jev-live.cjs
node scripts/verify-jev-live.cjs --codex-only
```

설치 위치는 `%LOCALAPPDATA%/Herdr/jev/`이고, 사용자 설정/교체 파일의 백업은 `%LOCALAPPDATA%/herdr-app-backups/jev-<고유값>/`다. `credential.dpapi`는 재설치 시 덮어쓰지 않는다. 선택된 앱 홈의 `data/jev/runtime.json`이 UI를 이 경로에 연결한다. 사용자별 키·설정·상태·백업은 Git에 포함하지 않는다.

상태가 **호출 확인 전**이면 해당 터미널의 훅 기록이 아직 없다는 뜻이다. 설치만으로 과거 요청을 재평가하지 않는다. 다음 실제 요청 뒤에도 계속 이 상태라면 전역 훅 비활성화, Codex 신뢰 상태, 사용자 프로필/원격 환경, 실행 중 엔진의 설정 반영을 점검한다. 필요한 경우만 같은 대화 ID로 재개한다. 모든 열린 대화를 강제로 종료·재시작하는 기능은 없다.

선택 확률 0.75와 confidence 0.5 이상일 때 작업 종류/검증 방식을 안내한다. 이는 초기 보수적 기준이며 사용자 업무 데이터로 정확도를 보증하거나 보정한 값은 아니다. 낮은 확신이면 호출 결과는 **최근 판단 불확실**로 남고 기존 AI가 판단한다. API 응답 제한은 4초이며 요청 앞에서 재시도하지 않는다. PowerShell 시작과 로컬 메타데이터 조회 시간은 별도로 더해진다.

## 개발·검증 기록

- 2026-11-06: 문서를 먼저 작성하고 API·전역 훅·현재 세션 구조를 재검증한 뒤 구현했다. 사용자 로컬 입력으로 암호화 키를 저장했고, 기존 설정을 백업한 후 두 엔진에 각각 SessionStart/UserPromptSubmit/SessionEnd 훅 3개를 설치했다. Codex의 해당 세 정의만 신뢰 등록했다.
- 실제 재검증에서 Codex 프로토콜의 소문자 시작 이벤트명, PowerShell의 인용된 실행 파일 호출 방식, 다른 셸의 PSModulePath 때문에 생긴 보안 모듈 자동 로딩 오류를 발견했다. 이벤트 매핑, 공통 셸 실행 구문, Windows PowerShell 내장 보안 모듈의 명시적 로딩으로 수정하고 회귀 테스트를 추가했다. 전역 실행 정책은 변경하지 않았다.
- TypeSafe 합성 API 시험: `jev-1.14.0`, 305ms, 입력 728/출력 137토큰. 한 번의 API 측정값이며 전체 훅 지연이나 모든 요청의 속도 보장은 아니다.
- 실제 Claude 2.1.318 및 Codex 0.166.0에서 Jev 훅과 API 호출을 확인했다. Codex는 모델에 미리 알려주지 않은 요청별 확인 UUID를 정확히 반환해 추가 문맥 전달까지 통과했다. Claude는 `usage_limit_reached`(429)로 모델 호출 전에 종료되어 최종 문맥 활용 검증은 남아 있다. 사용 한도 회피나 다른 계정/모델 전환을 하지 않았다.
- 최종 전체 Node 회귀: **75개 중 71개 통과, 기존 환경 의존 4개 건너뜀, 실패 0개**. Windows DPAPI/Shell 검사는 실제 사용자 컨텍스트에서, PowerShell 실행 허용은 테스트 프로세스에만 적용했다. Jev 자체 검사는 21개이며 모두 통과했다.
- 소스와 설치 mod의 native 검사, 실제 하단 상태 표시 및 상세 창 렌더링 확인. 앱 errors=[]이며 현재 선택 대화와 core/AI 프로세스를 유지했다. 새 설정의 실제 수신 여부를 확인하지 않은 기존 35개 대화를 성공으로 표시하지 않았다. 시험은 새 임시 작업 폴더/합성 터미널 식별자를 사용했으며 실제 새 워크스페이스를 UI에서 생성하거나 기존 사용자 대화에 시험 메시지를 보내지는 않았다.
- 자동 모델 변경·다른 탭 지시·자동 compaction·역할별 작업트리 생성은 이번 구현 범위에 포함하지 않았다. 기본 동작은 모든 대상 요청의 판단·짧은 참고 문맥 전달·상태 표시다.
